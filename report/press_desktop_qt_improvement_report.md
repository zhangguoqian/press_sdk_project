## 1. 实测结论（2026-11-19 加压对比）

测试条件：单独模式，设定压力 1.00 Ton、补压 1.00 Ton，由上位机启动、运行约 27 秒后停止。

| 项目 | HMI 屏幕 | 上位机 RT JSON | 一致性 |
|---|---|---|---|
| 当前阶段 | 0/6、1/6 | 0/6、1/6 | 一致 |
| 设定压力 / 补压 | 1.00 / 1.00 Ton | 1.0 / 1.0 | 一致 |
| 保压计时 | 5:12 → 5:08 → 4:58 | 5:12 → 5:09 → 4:58 | 一致 |
| 保温计时 | 8:20 | 08:20 | 一致 |
| 实时压力 | 16.50 / 22.19 / 29.96 Ton | 2.1 / 6.9 / 17.1 | 不一致 |
| 模具压强 | 1616.8 / 2174.8 / 2936.3 | 32.18 / 39.01 / 34.16 | 不一致 |
| 上/下板温度（未加热） | 0.0 / 0.0 °C | 0.0 / 0.0 | 一致 |

### 1.1 根因：DEBUG 固件屏幕显示与 RT 上报是两套公式

- `auto_hot_press/src/zgq.h`：`#define DEBUG_VERSION 1`
- `auto_hot_press/src/logic/mainLogic.cc`
  - 屏幕实时压力：`15*sin(0.1*index)+15`（0~30），L238-L254
  - RT `PValue`：`10*sin(P)+10`（0~20），且 `P` 每次 +0.1，相位与 `index` 不同步，L315-L328
  - 屏幕模具压强：用假压力代入 `tonToMpaCircle(value, D)`，得到 1600~2900（L297-L307）
  - RT `MoldPressure`：`20*cos(M)+20`（20~40），L320（**上位机已不再使用该字段**，模具压强改由实时压力计算，见 2.6）
  - 屏幕温度：`(150*sin(...)+150)*10`（L337-L341）
  - RT 温度：`TUp=30*sin(T)+30`、`TDown=18*cos(D)+18`（L425-L436）
- 因此两条曲线数值范围、相位都不同，比例随机变化，表现为“比例偏差”；模具压强屏幕值（GPa 级）物理上不可能，也是调试假数据的直接证据。

### 1.2 处理建议

1. 关闭 `DEBUG_VERSION` 重新编译并烧录 HMI，再对比真实传感器值（首选）。
2. 如必须用调试固件联调，应让屏幕显示与 RT 上报使用同一套公式。
3. 上位机侧字段映射无需修改；建议增加“调试/发布固件”识别与提示（见 2.2）。

## 2. 高优先级改进

### 2.1 通讯看门狗与断线重连（P0）✅ 已完成

已实现：
- `PressService` 在每次 RT 回调记录时间戳，1 s 定时检查：
  - 超过 **3 s** 未更新 → 进入 stale：侧栏显示“通讯中断”、日志 WARN、弹提示；
  - 超过 **10 s** → 自动重连，退避 **2/5/10/30 s**，失败持续重试；
  - 数据恢复或重连成功 → 自动清除 stale、停止重连并记录“通讯已恢复”。
- stale 期间 `MachineState::sdkMode()` 仍为真，实时值冻结在最后一帧，**不会退回本地模拟**。
- 内容区显示“通讯中断 / 正在尝试自动重连（第 N 次，M 秒后）”遮罩，底栏启动/排气/加热/合作按钮禁用。
- 连接中点“断开”变为“取消”，可中止在途连接；重复点击连接会提示“正在连接中”。
- 手动断开/取消会停止自动重连，并清空待确认指令与待写参数。
- 自动重连失败只记日志、不反复弹窗；手动连接失败保留错误原因。

验证：编译通过；COM4 实机连接运行无 3 s 误报。拔插串口触发路径需现场验证。

### 2.2 识别调试固件并显著提示（P0）⏳ 待办

现状：DEBUG 固件上报合成数据，上位机无法辨别，现场极易误判为“传感器故障”。

建议：
- 连接后记录并显示固件版本（HMI 已显示 `TYPE345 V3.1.5`，若协议无版本字段，推动固件在 ReadOnlyData 增加 `DebugBuild`/`FirmwareVersion`）。
- 若为调试固件：界面顶部显示“调试数据”水印/角标，日志记录 WARN，导出日志时附带标记。
- 联调文档与 `record.md` 中固定写明“DEBUG 固件压力/温度为模拟值”。

### 2.3 倒计时单位（P0）✅ 已完成

结论：**单独模式与合作模式的 `PTime` / `TTime` 单位均为秒**。

处理：
- 上位机统一按秒解析并显示为 `mm:ss`，不做毫秒判定或换算；
- 实测合作模式曾出现 `601000`，按秒解析会显示较大数值，这属于固件上报数值异常，应修改下位机数据，而不是在上位机做单位自适应；
- `record.md` 已同步注明“单模式/合作模式均为秒”。
- 测试建议：对 `312`、`3600`、`35999` 等秒值验证 `mm:ss` 显示即可。

### 2.4 指令下发确认与超时（P1）✅ 已完成

已实现：
- 启动/停止加压、加热、合作流程、模式切换在 SDK 调用成功后登记待确认指令；
- 每帧 RT 校验：`IsPStart`、`IsTStart`、`ModelState`；
- 确认后日志记 `指令已生效：xxx`；
- **3 s** 内未变化 → 提示 `指令未生效：xxx（3 s 内未检测到状态变化，实际：…）`，日志级别 ERROR。
  - 采用 3 s 而非原建议的 2 s：实测启动加压从下发到 RT 确认耗时 **1.83 s**，2 s 易误报。
- 待确认期间底栏控制按钮禁用；确认、超时、断开或重连后恢复/清理。

验证：启动加压 `23:32:55.521 → 23:32:57.348 指令已生效：启动加压`；停止指令下发成功，设备回到 0/6、压力 0.00。超时分支未在实机触发。

### 2.5 参数写入去抖与批量（P1）✅ 已完成

已实现：
- 所有参数写入排队：同一参数（key）400 ms 内连续修改只保留最后一次值，超时后批量下发；
- 覆盖压力段、温度段、合作段、段数、单独模具、合作模具类型/尺寸；
- 一次批量成功后只记一条汇总日志：`参数已下发：压力段 1、温度段 2`；
- 写入失败自动重试 1 次，仍失败提示 `参数下发失败：压力段 1（原因）`；
- 启动加压/加热/合作前强制 flush 未下发参数，失败则取消启动；模式切换前先 flush；
- 断开/重连/取消连接时清空待写队列。

验证：编译通过、COM4 连接与实时数据正常。连续快速编辑的 400 ms 合并效果需界面操作确认。

### 2.6 实时字段应用与参数联动（P0）✅ 已完成（2026-11-20）

- **`FlowChange`**：0 无操作；1/2/3 表示下位机 Press / Temp / Mix 参数 JSON 已变更。上位机收到后自动重新读取对应 JSON 并刷新界面；同一非 0 值只处理一次，回到 0 后重新生效；重读动作切回界面线程执行，避免阻塞 1 s 采集循环，失败写 WARN 日志。
- **`IsAir`**：按“是否允许排气”的能力位使用。为 1 时底栏“排气”按钮可用，点击后下发 SDK `startAir`（`CMDID_SET_START_AIR` 0x1524）；为 0 时按钮禁用并提示“设备当前不支持排气”。按钮已调整到“启动加压”之前；本地模拟模式不受该字段限制。
- **`MoldPressure`**：设备不再上报该字段，界面“模具压强”统一由实时压力计算：`PValue(ton) × 9806.65 / 模具面积(mm²)`（MPa），异形模具无面积时显示 `—`。
- **显示精度**：`PDecimal` 控制压力（Ton）小数位，`PressDecimal` 控制模具压强（MPa）小数位；压力表格、实时压力与设定压力统一生效。
- **自动补压**：`Max_Min` 为自动补压差，修改某段压力后该段补压设定自动更新为 `压力 - Max_Min`（最小 0）。
- **设备标识**：`NameZH`（为空回退 `NameEN`）更新窗口标题、侧栏品牌名与设置页品牌区；`Type` 更新侧栏副标题与设置页副标题，界面不再显示版本号。
- **模具类型**：切换模具类型时先下发 `setMoldType`（0 异形 / 1 圆形 / 2 矩形），再下发对应尺寸。
- **模式切换**：记录主动切换的目标模式，3 s 内忽略旧 `ModelState` 帧，避免设备确认前的页面闪回；设置页不跟随设备模式自动跳转。
- **曲线**：移除实时曲线底部“-180 s / 现在”文字刻度，避免与图例重叠。

验证：编译通过；上述字段解析、命令下发与界面联动已按功能分批提交（见 7.1）。实机验证 `FlowChange` 自动重读、`IsAir` 按钮启用与 `startAir` 排气效果待设备可用时确认。

## 3. 中优先级改进

### 3.1 数据质量与显示 🟡 部分完成

- 实时压力增加 3 点滑动平均，抑制末位跳动；小数位仍由 `PDecimal`（Ton）与 `PressDecimal`（MPa）控制。
- 温度上报负值（HMI 断线时为 `-1`）在数值区与图例统一显示 `—`，不再出现 `-1.0 °C`。
- `MoldPressure` 不再解析：模具压强由实测压力与模具面积计算，单位统一为 MPa。
- 原始值零漂（停机时 `PValue≈2.494`、`TDown≈2.136`）暂不做界面去皮，是否增加显示层校准待现场确认。
- 验证：编译通过；温度占位符与压力平滑可在模拟模式验证，零漂效果待设备可用时观察。

### 3.2 状态一致性 ✅ 已完成

- 设备侧启动提示：RT 状态由停止变为运行时，若上位机 5 s 内未下发对应启动指令，Toast 提示“检测到下位机已启动加压 / 加热”，按钮与页面随 RT 同步，避免误判。
- 停止类操作增加二次确认（停止加压、停止加热、停止合作流程），防止误触停止由下位机启动的流程。
- 未连接设备时明确标识模拟模式：窗口标题追加“· 本地模拟”，底栏状态提示以“本地模拟”开头，与真实运行区分。
- 模式切换：主动切换后 3 s 内忽略旧 `ModelState` 帧，设置页不跟随设备模式自动跳转，页面不再闪回。

### 3.3 日志功能 ✅ 已完成

已实现：
- 时间格式 `yyyy-MM-dd HH:mm:ss.zzz`，包含日期；
- 新增 `core/loglevel.h`，`PressService::logMessage(message, level)` 支持显式 INFO/WARN/ERROR；Toast 等旧调用保留关键字推断兜底；
- 自动落盘：`%APPDATA%\AUTO HOT PRESS\自动热压机 · 上位机\logs\yyyyMMdd.log`，单文件 5 MB 轮转 `.1.log`，保留 7 天；
- 过滤时显示 `匹配 N / 共 M`，无过滤显示总条数；
- 面板高度可拖动调整（110~520 px）；
- 导出成功/失败 Toast 提示，成功后自动打开目录；无日志时提示；
- 5 s 内相同消息合并为一行并显示 `（×N）`，原始出现仍写入文件。

验证：实机生成 `20261119.log`（807 字节），内容与界面一致；完整日期显示正常。过滤计数、拖拽、导出弹窗、重复合并需界面操作确认。

### 3.4 启动连接流程与本地模拟 ✅ 已完成

已实现：
- 程序启动后自动弹出设备连接对话框，提供 **串口 / 网络 / 本地模拟** 三种方式；对话框显示期间主界面隐藏，选择完成后再显示；
- 选择“本地模拟”后不访问真实设备，直接进入主界面，Toast 与侧栏显示“本地模拟运行”；
- 启动对话框中的“退出”按钮直接关闭软件（不再只是关闭对话框）；
- 侧栏移除独立的“连接”入口，连接统一由启动对话框或系统设置发起；
- 系统设置 → 设备通讯：端点只读展示，按钮显示“断开连接 / 连接设备”，断开后重新打开连接对话框（对话框期间同样隐藏主界面）；
- `--sdk <地址>` 启动参数保留自动连接，不弹对话框，便于自动化与产线调试；`--screenshot/--annotate` 也不弹连接框。

验证：启动对话框三种选项显示正常；本地模拟可进入主界面；连接 COM4 后在系统设置点击“断开连接”会断开并重新弹出对话框（截图确认）；主界面在连接选择期间不再闪现。

## 4. 工程质量与可维护性

### 4.1 测试 ⏳

- 缺少单元测试：建议为 `PressService` 的四类 JSON 解析、时间格式化、阶段边界、倒计时单位判定、指令确认状态机、参数去抖合并增加测试（Qt Test / ctest）。
- 建议加入样例报文 fixtures（ReadOnly/Press/Temp/Mix/RealTime），防止固件字段变化导致静默回归。

### 4.2 构建 ⏳

- CMake 将 Qt 路径硬编码为 `mingw81_32`；根目录曾出现 32 位编译器 + 64 位 Qt 混用导致链接失败。
- 建议：统一一种工具链；Qt 路径通过 `CMAKE_PREFIX_PATH` 或环境变量注入；在 README 写明构建步骤与套件要求。
- 根 `CMakeLists.txt` 中 `add_subdirectory(example/Qt)` 被注释，需要说明原因或删除旧示例。

### 4.3 代码结构 ⏳

- `MachineState` 同时承担协议适配、业务状态与本地模拟，职责偏重；建议拆为：
  - `ProtocolAdapter`（JSON → 领域模型）
  - `MachineState`（业务状态与规则）
  - `Simulator`（未连接时的模拟推进）
- `PressService` 中 SDK 回调线程与 UI 线程边界建议统一注释说明；`m_loggedFirstRt`、`m_lastRtMs` 等跨线程字段需明确约束。
- 魔法数字（1 s 采样、3 s 超时、500 条日志、400 ms 去抖、156 px 初始高度）建议集中为常量或配置。

### 4.4 可配置性 ⏳

- 采样周期、重连间隔、日志上限/保留天数、去抖时长建议放入配置（QSettings 或 ini）。
- 参数是否本地持久化需明确：当前仅保存连接端点，工艺参数依赖设备侧存储。
